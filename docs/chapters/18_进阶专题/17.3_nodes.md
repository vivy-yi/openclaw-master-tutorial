# 13.3 移动端节点：iOS、Android 与语音交互

OpenClaw 节点（Nodes）是运行在移动设备上的客户端，提供语音交互、语音唤醒等功能。

---

## 13.3.1 节点概述

OpenClaw 支持三种主要节点平台：

| 平台 | 语音唤醒 | 语音通话 | 语音转文字 |
|------|----------|----------|------------|
| **macOS** | ✅ | ✅ | ✅ |
| **iOS** | ✅ | ✅ | ✅ |
| **Android** | 手动 | ✅ | ✅ |

### 核心功能

```
┌─────────────────────────────────────────────────────────────┐
│                      节点核心功能                            │
├─────────────────────────────────────────────────────────────┤
│                                                             │
│  1. Voice Wake (语音唤醒)                                  │
│     └── 全局唤醒词列表，由 Gateway 统一管理                  │
│                                                             │
│  2. Talk Mode (语音通话模式)                                │
│     └── 持续语音对话 → 语音转文字 → 模型处理 → TTS 输出   │
│                                                             │
│  3. Audio / Voice Notes (语音消息)                          │
│     └── 接收语音消息 → 自动转录 → 注入对话上下文          │
│                                                             │
└─────────────────────────────────────────────────────────────┘
```

## 13.3.2 Voice Wake（语音唤醒）

OpenClaw 将**唤醒词视为单一全局列表**，由 **Gateway 所有**。

### 核心特性

- **无每节点自定义唤醒词**
- **任何节点/应用 UI 都可以编辑**；更改由 Gateway 保留并广播给所有人
- macOS 和 iOS 保留本地的 **Voice Wake 启用/禁用开关**
- Android 目前保持 Voice Wake 关闭，使用语音标签中的手动麦克风流程

### 存储位置

唤醒词存储在 Gateway 机器上：

```
~/.openclaw/settings/voicewake.json
```

### 格式

```json
{
  "triggers": ["openclaw", "claude", "computer"],
  "updatedAtMs": 1730000000000
}
```

### 协议

**方法**：
- `voicewake.get` → `{ triggers: string[] }`
- `voicewake.set` → `{ triggers: string[] }`

**事件**：
- `voicewake.changed` → `{ triggers: string[] }`

谁接收：
- 所有 WebSocket 客户端（macOS 应用、WebChat 等）
- 所有连接的节点（iOS/Android），节点连接时作为初始"当前状态"推送

### 各平台行为

| 平台 | Voice Wake 模式 | 行为 |
|------|----------------|------|
| **macOS** | Background | 使用全局列表控制 `VoiceWakeRuntime` 触发 |
| **iOS** | Background | 使用全局列表进行 `VoiceWakeManager` 触发检测 |
| **Android** | **Foreground (v2026.7.2+)** | ✅ 前景 Voice Wake，支持持续唤醒监听 |
| **Linux (headless)** | N/A | 通过配对节点使用，不支持 Voice Wake |

## 13.3.3 Android Foreground Voice Wake (v2026.7.2+)

v2026.7.2 为 Android 新增了**前景 Voice Wake**功能，在前台运行时持续监听唤醒词，无需手动触发麦克风。

### 与 iOS/macOS 的区别

| 特性 | iOS/macOS Background Wake | Android Foreground Wake |
|------|---------------------------|-------------------------|
| **监听模式** | 后台持续监听 | 前台持续监听 |
| **电池影响** | 低（系统优化） | 较高（需要前台服务）|
| **唤醒灵敏度** | 系统自动调整 | 可手动配置 |
| **持续对话** | 需每次唤醒 | 支持持续对话 |

### Android Foreground Wake 配置

```kotlin
// Android: 前景 Voice Wake 配置
val voiceWakeConfig = VoiceWakeConfig(
    mode = ForegroundMode,  // 新增 ForegroundMode
    wakeWord = "Hey OpenClaw",
    continuous = true,       // 持续监听
    noiseThreshold = 0.7f,   // 噪音阈值
    activationDelay = 500    // 激活延迟(ms)
)
```

### 启用/禁用

Android 的 Voice Wake 启用/禁用仍然使用**全局列表**，由 Gateway 统一管理，与 macOS/iOS 一致。

```bash
# 查看所有启用的唤醒词
gateway voicewake list

# 添加 Android 专用唤醒词
openclaw voicewake add "Hey OpenClaw" --platform android

# 禁用 Android Voice Wake
openclaw voicewake disable --platform android
```

### 限制

- **前台要求**：Android 需要 OpenClaw 应用在前台运行
- **省电策略**：部分厂商定制 Android 系统可能限制后台活动
- **权限要求**：麦克风权限 + 后台弹出界面权限

## 13.3.4 Linux 节点能力扩展 (v2026.7.2+)

v2026.7.2 为 **headless Linux 节点**新增了摄像头、位置、通知能力暴露，使其与其他移动节点平台能力看齐。

### 新增能力对比

| 平台 | 摄像头 | 位置 | 通知 |
|------|--------|------|------|
| **macOS** | ✅ | ✅ | ✅ |
| **iOS** | ✅ | ✅ | ✅ |
| **Android** | ✅ | ✅ | ✅ |
| **Linux (headless)** | ✅ **新增** | ✅ **新增** | ✅ **新增** |

### 配置示例

```yaml
# headless node 配置
node:
  platform: linux
  host: linux-node-01.local
  capabilities:
    camera: true      # 新增：支持摄像头捕获
    location: true     # 新增：支持位置获取
    notifications: true  # 新增：支持系统通知
    audio: false       # Linux 通常无音频输出
```

### 摄像头能力

```bash
# 从 Linux 节点捕获摄像头画面
openclaw node camera --node linux-node-01 --snapshot

# 持续监控
openclaw node camera --node linux-node-01 --stream
```

### 位置能力

```bash
# 获取 Linux 节点位置（通过 IP 地理位置或 GPS 设备）
openclaw node location --node linux-node-01

# 预期输出
# latitude: 31.2304
# longitude: 121.4737
# accuracy: 100m
# source: ip-geolocation
```

### 通知能力

```bash
# 从 Linux 节点发送通知
openclaw node notify --node linux-node-01 --title "Alert" --body "Task completed"

# 支持图标和优先级
openclaw node notify --node linux-node-01 \
  --title "Warning" \
  --body "High CPU usage detected" \
  --urgency critical
```

### 与移动节点的区别

| 能力 | 移动节点（iOS/Android） | Linux 节点 |
|------|----------------------|-----------|
| **摄像头** | 系统相机 App | V4L2 /dev/video* |
| **位置** | GPS / 网络定位 | IP 地理位置或外接 GPS |
| **通知** | 系统通知 | libnotify /notify-send |

## 13.3.5 Talk Mode（语音通话模式）

Talk mode 是一个**持续的语音对话循环**：

```

![移动节点]/assets/diagrams/20_nodes_mobile.png)


1. 聆听语音
2. 发送转录文本给模型（主会话，chat.send）
3. 等待响应
4. 通过 ElevenLabs 播放（流式播放）
```

### macOS 行为

- **始终开启的覆盖层**（启用 Talk 模式时）
- **Listening → Thinking → Speaking** 阶段转换
- **短暂停**（静音窗口）时，当前转录被发送
- 回复写入 **WebChat**（与打字相同）
- **说话时中断**（默认开启）：如果用户开始说话，停止播放并记录中断时间戳

### 回复中的语音指令

助手可以在回复前加上 **单个 JSON 行** 来控制语音：

```

![移动节点]/assets/diagrams/20_nodes_mobile.png)

json
{ "voice": "<voice-id>", "once": true }
```

规则：
- 仅第一行非空行
- 未知键被忽略
- `once: true` 仅适用于当前回复
- 没有 `once`，语音成为 Talk 模式的新默认

支持的键：
- `voice` / `voiceId`
- `model` / `modelId`
- `speed`, `stability`, `similarity`, `style`, `speakerBoost`

### 配置

```json5
{
  talk: {
    voiceId: "elevenlabs_voice_id",
    modelId: "eleven_v3",
    outputFormat: "mp3_44100_128",
    apiKey: "elevenlabs_api_key",
    silenceTimeoutMs: 1500,
    interruptOnSpeech: true,
  },
}
```

默认值：
- `interruptOnSpeech`: true
- `silenceTimeoutMs`: 平台默认（macOS 700ms，iOS 900ms）
- `voiceId`: 回退到 `ELEVENLABS_VOICE_ID`
- `modelId`: 默认为 `eleven_v3`

## 13.3.6 Audio / Voice Notes（语音消息）

OpenClaw 可以接收语音消息、自动转录并注入对话上下文。

### 工作流程

```
1. 定位第一个音频附件，下载（如需要）
2. 强制执行 maxBytes 限制
3. 按顺序运行第一个符合条件的模型
4. 失败则尝试下一个
5. 成功时用 [Audio] 块替换 Body 并设置 {{Transcript}}
```

### 自动检测（默认）

如果未配置模型，OpenClaw 自动检测顺序：
1. **本地 CLI**：sherpa-onnx-offline、whisper-cli、whisper
2. **Gemini CLI**
3. **提供商**：OpenAI → Groq → Deepgram → Google

### 支持的提供商

- OpenAI (`gpt-4o-mini-transcribe`)
- Deepgram (`nova-3`)
- Mistral (`voxtral-mini-latest`)

### 配置示例

```

![移动节点]/assets/diagrams/20_nodes_mobile.png)

json5
{
  tools: {
    media: {
      audio: {
        enabled: true,
        maxBytes: 20971520,
        models: [
          { provider: "openai", model: "gpt-4o-mini-transcribe" },
        ],
      },
    },
  },
}
```

### 群聊中的语音消息

当为群聊设置 `requireMention: true` 时，OpenClaw 在检查提及之前会转录音频。

## 13.3.8 本节小结

1. **Voice Wake**：全局唤醒词列表，Gateway 统一管理；Android 新增 Foreground Wake
2. **Talk Mode**：持续语音对话循环，ElevenLabs TTS
3. **语音消息**：自动转录，注入对话上下文
4. **Linux 节点扩展**：v2026.7.2 新增摄像头、位置、通知能力
5. **平台差异**：macOS 功能最全，Linux 节点能力持续完善
